Entity Relationship diagram, is one type of [[1.2 DB design]]

this consists of: 
# 1- Entity 
is anything in your system 

## strong vs weak entities   

a weak entity has no purpose if the strong entity connected to it disappeared, that's why its weak, its dependent on the strong one. 

usually weak entities are uncommon 

the primary key for the weak entity is called a partial key, because it needs the PK from the strong entity 
# 2- Attributes 
they describe the entity 

## attribute types 

- simple:
	cannot be broken down into multiple attributes
	is not calculated at runtime 
	only one fot each entity

- derived: can be calculated from other attributes 
- multi valued: self explanatory
- composite: also self explanatory 
- complex: multi valued AND composite

## Types of a Relationship 

### 1- unary
or a recursive relationship, example: An Employee manages other employees , or a person marrying another person 
### 2- binary
normal relationship 
### 3- ternary 

a relation between three entities

 

the shipping mode differs according to the vendor, warehouse and the product, so this attribute it shared between all three

## Cardinalty 

describes the relation 
### one to one 
example: each project has one manager, and each manager only manager one project at a time 

### one to many 

example: each employee has one department, but each department has many employees 

### many to many 

example: each student can take many courses, and each course can be taken by many students 


## Participation 

### Total  Participation 
if every one "row" from this entity is *participated* in the relation  
its denoted with a double line 

any weak entity has Total  Participation 
### Partial  Participation 
not every row has to participate 

example: each employee MUST have a department, but not every employee has to manage a department 

so  the **work** relation between emp and dep is total  Participation but the **manages** is partial 


# Keys 

keys are special attributes

## Primary Key

a unique attribute that describes the entity, its denoted by <u>an underline</u>

## Candidate Key

those are the attributes that can be PK,  you only chose one of them 

if no CD Keys, you make up a PK by joining two attributes
